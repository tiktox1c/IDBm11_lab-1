# Локальная система обработки изображений

Учебный материал по дисциплине «Программно-аппаратное обеспечение искусственного интеллекта».

В этом примере приложение получает изображение и определяет класс показанного объекта с помощью заранее обученной модели. Модель выполняется локально на центральном процессоре. Учебный пример описывает конкретную конфигурацию и порядок её работы.

## Аппаратные компоненты

Центральный процессор CPU — компонент, который выполняет инструкции программы и вычисления модели.
Оперативная память RAM — компонент, который временно хранит параметры работающей модели и подготовленные входные данные.
Твердотельный накопитель SSD — компонент, который постоянно хранит файлы модели и изображения.

Оперативная память энергозависима: после выключения питания её рабочее содержимое теряется. Файлы, записанные на накопитель, сохраняются после выключения питания. В рассматриваемой конфигурации вычисления выполняет CPU, а накопитель используется для хранения файлов.

---

## Программные компоненты

Интерпретатор Python — программа, которая выполняет код приложения на языке Python.
Драйвер устройства — программа, которая обеспечивает взаимодействие операционной системы с устройством.
Планировщик операционной системы — компонент, который распределяет процессорное время между выполняемыми задачами.

Виртуальное окружение Python хранит отдельный набор библиотек проекта. В данном учебном проекте каталог виртуального окружения называется .venv. Сам интерпретатор Python устанавливается до создания виртуального окружения.

Модель хранится в виде файла с параметрами. Приложение использует эти параметры для вычисления результата; запуск уже обученной модели не является её повторным обучением.

---

## Загрузка модели для работы

В описанном приложении загрузка и запуск модели выполняются строго в следующем порядке.
1. Прочитать файл модели с твердотельного накопителя.
2. Разместить прочитанные параметры модели в оперативной памяти.
3. Запустить вычисления модели на центральном процессоре.

Второй этап использует данные, прочитанные на первом этапе. Третий этап начинается после размещения параметров в оперативной памяти. Поэтому перестановка этапов нарушает описанную процедуру.

В этой процедуре накопитель предоставляет файл, оперативная память хранит рабочие параметры, а центральный процессор выполняет вычисления. Эти роли различаются даже тогда, когда все компоненты находятся в одном компьютере.

---

## Обработка изображения обученной моделью

После готовности модели приложение обрабатывает каждое новое изображение строго в следующем порядке.
1. Получить входное изображение из выбранного файла.
2. Преобразовать полученное изображение в формат входных данных модели.
3. Передать подготовленные данные модели и получить предсказанный класс объекта.

Второй этап использует изображение, полученное на первом этапе. Третий этап требует подготовленных входных данных. Предсказанный класс является результатом применения уже обученной модели.

Результат классификации — название класса объекта. Подготовка входных данных изменяет представление изображения, а вычисление модели определяет предсказанный класс. При работе описанного приложения параметры модели не обучаются заново.
